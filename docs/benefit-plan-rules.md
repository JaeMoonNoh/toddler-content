# 혜택 일정·금액 초안 규칙

`pnpm benefit plan-texts <지역코드> <폴더>`로 만든 원문 md를 읽고 초안을 쓸 때 따르는 규칙. 초안은 `pnpm benefit plan-check`로 검사하고 `pnpm benefit plan-apply`로 혜택 목록에 넣는다.

## 목표

임신·출산 혜택 사이트가 출산예정일로 **신청 기간을 날짜로 계산**하고, **받는 금액을 합계**로 보여준다. 카드마다 일정(schedule), 금액(amount), 올해 신청 기간(applicationPeriod)을 원문에 근거해 채운다. 인천·서울을 이 규칙으로 채웠다.

**원문에 없는 내용은 절대 추측하지 않는다.** 원문으로 정할 수 없으면 그 필드는 `null`로 두고 `note`에 이유를 적는다. 다른 검토자가 원문과 대조하고, 운영자가 PR에서 승인한다.


## 출력

카드마다 아래 모양 하나. 배열 하나로 JSON 파일에 쓴다. 카드 순서는 원문 파일 순서 그대로.

```json
{
  "slug": "gov24-611000019618",
  "schedule": { ... } | null,
  "amount": { ... } | null,
  "applicationPeriod": { ... } | null,
  "note": "판단이 애매했던 점. 없으면 빈 문자열"
}
```

`basis.url`은 언제나 그 카드의 "원문 링크"를 그대로 쓴다. `basis.text`는 원문 문장을 **그대로** 짧게 인용한다. 여러 곳이면 ` / `로 잇는다. 말을 바꾸거나 요약하지 않는다.

## 1. 일정 (schedule)

원문에 **임신 주수나 출생일(출산일)을 기준으로 한 신청 시작·마감**이 있을 때만 쓴다. "연중 상시신청", "상시", 기준일 없는 마감은 `null`.

```json
{
  "from": { "anchor": "pregnancy" | "birth", "months": 0, "days": 0 },
  "until": { "anchor": "pregnancy" | "birth", "months": 0, "days": 0 },
  "untilLabel": "신청 마감 (출산 후 90일)",
  "summary": "사용자에게 보여줄 한 줄 (해요체)",
  "basis": { "text": "원문 인용", "url": "원문 링크" }
}
```

- `anchor: "pregnancy"`는 임신 시작(출산예정일 280일 전, 임신 0주). 임신 N주 = `days: N*7`. 예: 임신 12주 → `days: 84`, 임신 32주 → `days: 224`.
- `anchor: "birth"`는 출생일(태어나기 전에는 출산예정일).
- "출산일로부터 90일 이내"는 출산일 포함 90일째까지라서 `{ anchor: "birth", months: 0, days: 89 }`. 같은 식으로 "60일 이내"는 `days: 59`.
- "출생 후 1년 이내", "12개월 이내"는 `{ anchor: "birth", months: 12, days: -1 }`. "6개월 이내"는 `months: 6, days: -1`.
- 시작이 따로 없고 출생 뒤 마감만 있으면 `from`은 `{ anchor: "birth", months: 0, days: 0 }`.
- 출산 전에 신청해야 하면(예: "출산예정일 전일까지") `until`은 `{ anchor: "birth", months: 0, days: -1 }`. 시작이 "임신 확인 후"면 `from`은 `{ anchor: "pregnancy", months: 0, days: 0 }`.
- 나이마다 해마다 신청하는 것(예: 2·3·4세 때 각각)은 **첫 번째 기간만** 적고, summary에 반복된다고 쓴다.
- `untilLabel` 예: "신청 마감 (출산 후 90일)", "신청 마감 (출생 후 1년)", "출산 전까지".
- `summary` 예: "임신 12주부터 출산 후 90일 안에 신청해요. 서울에 3개월 이상 살아야 해요". 거주 기간 요건이 원문에 있으면 덧붙인다.
- 마감이 **출생신고일** 기준이면 출생일 기준으로 계산하고 summary에 "마감은 출생일 기준으로 계산했어요"를 덧붙인다. 출생신고는 출생 뒤라서 실제 마감과 같거나 이르다.
- 백일해 예방접종처럼 **받을 수 있는 시기**가 원문에 정해져 있으면 신청기한이 "상시"여도 그 시기를 일정으로 적는다 (예: 임신 27~36주 → `days: 189` ~ `days: 252`).
- 마감이 서비스 종료일, 시술일, 입양신고일처럼 출생일로 계산할 수 없는 날 기준이면 `null`.

인천 예시:

```json
{"from":{"anchor":"pregnancy","months":0,"days":224},"until":{"anchor":"birth","months":0,"days":89},"untilLabel":"신청 마감 (출산 후 90일)","summary":"임신 32주부터 출산 후 90일 안에 보건소나 정부24에서 신청해요. 인천에 1년 이상 살아야 해요","basis":{"text":"신청시기 : 임신 32주부터 출산일로부터 90일 이내","url":"..."}}
```

```json
{"from":{"anchor":"birth","months":12,"days":0},"until":{"anchor":"birth","months":12,"days":119},"untilLabel":"첫해(만 1세) 신청 마감","summary":"만 1세부터 7세까지 해마다 생일 뒤 120일 안에 신청해요. 기간이 지나면 그해 지원금은 받지 못해요","basis":{"text":"신청기한: 아동의 생일 이후 120일 이내(신청 기간이 지나면 당해연도 천사지원금 지원불가) / 대상: 2023. 1. 1. 이후 출생한 1세~7세 아동","url":"..."}}
```

## 2. 금액 (amount)

받는 것이 있으면 쓴다. 원문에서 금액이나 내용을 알 수 없으면 `null`.

```json
{
  "kind": "cash" | "voucher" | "service" | "wage",
  "summary": "사람이 읽는 한 줄",
  "tiers": [ { "minBirthOrder": 1, "maxBirthOrder": null, "won": 500000 } ] | null,
  "basis": { "text": "원문 인용", "url": "원문 링크" }
}
```

- `kind`
  - `cash`: 현금(계좌 입금)
  - `voucher`: 이용권, 바우처, 포인트, 지역화폐·지역사랑상품권, 서울Pay 등
  - `service`: 물품, 검사, 대여, 방문 서비스, 감면처럼 돈이 아닌 것
  - `wage`: 일하지 못하는 동안 임금 대신 받는 급여 (출산휴가급여 등)
- `summary` 예: "교통비 70만원 (바우처)", "첫째 30만원, 둘째 50만원, 셋째 100만원, 넷째 이상 200만원", "기형아 검사, 엽산제·철분제, 유축기 대여".

### tiers (합계에 넣는 금액) — 아래를 **모두** 만족할 때만 채우고, 아니면 `null`

1. 카드의 "대상 묶음"이 **없음 (누구나)** 이다. 대상 묶음이 있으면(장애, 저소득, 다자녀, 난임, 입양 등) `null`.
2. 카드에 **조건**(고용보험, 어린이집 이용 등)이 없다. 있으면 `null`.
3. 금액이 **정해져 있다.** "최대", "이내", "~까지", "소득에 따라", "실비", "차등"이면 `null`.
4. `kind`가 `service`가 아니다.

채울 때:

- 받을 수 있는 **기간 전체의 총액**을 적는다. 매달·해마다 받으면 곱해서 더한다 (예: 해마다 120만원 × 7년 = 840만원). 그 계산을 summary에 보인다.
- 출생 순위에 따라 다르면 구간으로 나눈다. 구간은 첫째(1)부터 빈틈없이 이어지고, 마지막 구간의 `maxBirthOrder`는 `null`.
- 모두 같으면 `[{ "minBirthOrder": 1, "maxBirthOrder": null, "won": 금액 }]`.
- 쌍둥이에 따라 달라지는 금액은 단태아 기준으로 적고 summary에 쌍둥이 금액을 덧붙인다.

인천 예시:

```json
{"kind":"cash","summary":"출산지원금 첫째 500만·둘째 800만·셋째 1,300만·넷째 이상 2,000만원 + 양육비 + 생일축하금(6년간 해마다 20만원)","tiers":[{"minBirthOrder":1,"maxBirthOrder":1,"won":7400000},{"minBirthOrder":2,"maxBirthOrder":2,"won":11600000},{"minBirthOrder":3,"maxBirthOrder":3,"won":17800000},{"minBirthOrder":4,"maxBirthOrder":null,"won":28400000}]}
```

```json
{"kind":"voucher","summary":"산후조리비 150만원 (인천e음 포인트, 1년 안에 사용)","tiers":null}
```
(대상 묶음이 "저소득"이라 `null`)

```json
{"kind":"cash","summary":"월 50만원씩 6개월, 최대 300만원","tiers":null}
```
(육아휴직한 아빠만 받고 "최대"라서 `null`)

## 3. 올해 신청 기간 (applicationPeriod)

원문에 **연도가 박힌 신청 기간**(예: "2026.1.1.~2026.12.31.", "2026. 3. 2. ~ 3. 31.")이 있을 때만 쓴다. 상시신청이나 출생일 기준 마감은 여기가 아니라 schedule이다.

```json
{ "start": "2026-01-01", "end": "2026-12-31", "basis": { "text": "원문 인용", "url": "원문 링크" } }
```

올해 기간만 적는다. 이미 지난 기간이어도 적는다 (화면이 "마감됨"으로 보여준다). 작년 이전 기간뿐이면 `null`로 두고 note에 적는다.

## 4. 검사기가 막는 것

`pnpm benefit plan-check`가 아래를 잡는다. 초안을 쓸 때부터 지킨다.

- `schedule`, `amount`, `applicationPeriod`를 빠뜨림 (정할 수 없으면 `null`로 적는다)
- `basis.url`이 카드의 원문 링크와 다름
- 대상 묶음이나 조건이 있는 카드, `service`, summary에 "최대·이내·까지·차등·실비"가 있는 금액에 `tiers`를 채움
- 올해와 겹치지 않는 `applicationPeriod`
- 혜택 목록의 도메인 규칙 (빈 설명, 끝이 시작보다 앞인 일정, 첫째부터 이어지지 않는 금액 구간 등)

## 5. note에 꼭 적을 것

- 원문끼리 다르거나(보조금24와 복지로 내용이 다름) 날짜·금액이 애매한 것
- 원문에 "2024년 12월 31일까지 출생" 같은 출생 시기 제한이 있어서 지금 임신한 사람이 받을 수 없어 보이는 것 (카드를 뺄지 운영자가 정한다)
- 복지로 요약뿐이라 일정·금액을 정할 수 없는 것
